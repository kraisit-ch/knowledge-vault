Pull Request

วงจรของ Pull Request

  1. Sync main → สร้าง branch ใหม่ (git switch -c feature/ORD-123-…)
  2. Commit เล็ก ๆ แต่ละ commit build ผ่าน
  3. Self-review ดู diff ของตัวเองก่อนทุกครั้ง ลบ debug / โค้ดที่ comment ทิ้ง
  4. เปิด PR ตาม template + แนบภาพหน้าจอถ้าเป็นงาน UI
  5. CI ต้องเขียว: lint, type-check, test, build
  6. Reviewer อย่างน้อย 1 คน approve → Squash merge → ลบ branch

Code Review

Reviewer ดูอะไร (เรียงตามความสำคัญ)

🎯

1. ถูกต้อง

ทำตาม requirement ไหม edge case (null, ว่าง, ซ้ำ, พร้อมกัน) ครบไหม

🔒

2. ปลอดภัย

ตรวจสิทธิ์, validate input, SQL injection, secret หลุด, ข้อมูลส่วนบุคคล

🧩

3. ออกแบบ

อยู่ถูกชั้นไหม (Clean Architecture), ซ้ำกับของที่มีแล้วไหม

📖

4. อ่านง่าย

ชื่อสื่อความหมาย ฟังก์ชันไม่ยาวเกิน logic ซับซ้อนมีคำอธิบาย

⚡

5. Performance

N+1 query, re-render เกินจำเป็น, โหลดข้อมูลเกิน

🧪

6. Test

มี test สำหรับ logic ใหม่ / bug ที่แก้ (กันกลับมาเกิดซ้ำ)

เรื่อง format / ลำดับ import / ช่องว่าง ให้ เครื่องมือ (Prettier, ESLint, dotnet format) จัดการ ไม่ต้องเสียเวลาคอมเมนต์

Automation

CI ที่ทุก PR ต้องผ่าน

# .github/workflows/ci.yml (ย่อ)
on: [pull_request]
jobs:
  web:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm run lint && npx tsc --noEmit
      - run: npm test -- --run
      - run: npm run build
  api:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: "10.0.x" }
      - run: dotnet format --verify-no-changes
      - run: dotnet build -warnaserror
      - run: dotnet test --no-build

Cheat Sheet

คำสั่ง Git ที่ใช้บ่อย

# เริ่มงานใหม่
git switch main && git pull --rebase
git switch -c feature/ORD-123-cancel-order

# อัปเดต branch ให้ทัน main
git fetch origin
git rebase origin/main

# แก้ commit ล่าสุด (ยังไม่ push)
git commit --amend

# push branch ครั้งแรก
git push -u origin HEAD

# เก็บงานชั่วคราว
git stash push -m "wip: filter"
git stash pop

# ย้อน commit ที่ push ไปแล้ว (ปลอดภัย)
git revert <sha>

# ดูว่าใครแก้บรรทัดนี้
git blame -L 40,60 src/Order.cs

# หา commit ที่ทำให้เกิด bug
git bisect start
ห้าม git push --force บน branch ที่คนอื่นใช้ร่วม ถ้าจำเป็นบน branch ตัวเองให้ใช้ --force-with-lease
Definition of Done

งานจะนับว่า “เสร็จ” เมื่อ…

  • ☐ ทำครบตาม acceptance criteria ใน ticket
  • ☐ PR ได้รับ approve และ CI เขียว
  • ☐ มี test สำหรับ logic ใหม่
  • ☐ merge เข้า main แล้ว
  • ☐ deploy ขึ้น staging และทดสอบผ่าน
  • ☐ อัปเดตเอกสาร / API contract / .env.example
  • ☐ ไม่มี error ใหม่ใน log / monitoring
  • ☐ แจ้ง QA / PO พร้อมลิงก์ทดสอบ
“เสร็จบนเครื่องผม” ยังไม่นับว่าเสร็จ 🙂
