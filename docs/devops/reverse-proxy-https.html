ตัวอย่าง · Caddy

Caddy: HTTPS อัตโนมัติใน 6 บรรทัด

# Caddyfile
shop.example.com {
    encode zstd gzip
    handle_path /api/* {
        reverse_proxy api:8080
    }
    reverse_proxy web:3000
}

# compose.yaml (ส่วนของ proxy)
services:
  caddy:
    image: caddy:2.11-alpine
    ports: ["80:80", "443:443", "443:443/udp"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data          # เก็บ certificate (ห้ามหาย)
    restart: unless-stopped
volumes:
  caddy_data:
เงื่อนไขเดียว: DNS ของ shop.example.com ต้องชี้มาที่ IP ของ server และเปิด port 80/443 แล้ว Caddy จะขอและต่ออายุ certificate ให้เอง · handle_path ตัด /api ออกก่อนส่งต่อ ถ้า API ต้องการ path เต็มให้ใช้ handle แทน
ตัวอย่าง · Nginx

Nginx: config สำหรับ Next.js + .NET

server {
    listen 443 ssl;
    http2 on;
    server_name shop.example.com;

    ssl_certificate     /etc/letsencrypt/live/shop.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/shop.example.com/privkey.pem;

    client_max_body_size 20m;                       # ขนาด upload สูงสุด

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;        # WebSocket
        proxy_set_header Connection "upgrade";
    }
}
server { listen 80; server_name shop.example.com; return 301 https://$host$request_uri; }

ขอ certificate ด้วย sudo certbot --nginx -d shop.example.com แล้ว certbot ตั้งการต่ออายุอัตโนมัติให้ · ตรวจ config ด้วย sudo nginx -t ก่อน reload ทุกครั้ง

ตัวอย่าง · Traefik

Traefik: บอก routing ผ่าน label ของ container

services:
  traefik:
    image: traefik:v3.7
    command:
      - --providers.docker=true
      - --providers.docker.exposedbydefault=false
      - --entrypoints.web.address=:80
      - --entrypoints.websecure.address=:443
      - --certificatesresolvers.le.acme.httpchallenge.entrypoint=web
      - --certificatesresolvers.le.acme.email=devops@example.com
      - --certificatesresolvers.le.acme.storage=/letsencrypt/acme.json
    ports: ["80:80", "443:443"]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - letsencrypt:/letsencrypt

  web:
    image: ghcr.io/mercent/shop-web:1.4.2
    labels:
      - traefik.enable=true
      - traefik.http.routers.web.rule=Host(`shop.example.com`)
      - traefik.http.routers.web.entrypoints=websecure
      - traefik.http.routers.web.tls.certresolver=le
volumes:
  letsencrypt:

เพิ่มแอปใหม่ = ใส่ label ไม่ต้องแตะ config ของ proxy · Traefik ต้องอ่าน Docker socket จึงควรใช้แบบ read-only และดูแล server ให้ปลอดภัย

ปัญหาที่เจอบ่อยที่สุด

แอปข้างหลัง proxy ต้องเชื่อ X-Forwarded-*

proxy คุยกับแอปด้วย HTTP ธรรมดา ถ้าแอปไม่อ่าน header ที่ proxy ส่งมา จะคิดว่าผู้ใช้เข้ามาทาง HTTP → redirect วน, ลิงก์ login ผิด, cookie Secure ไม่ทำงาน, ได้ IP ผู้ใช้เป็น IP ของ proxy

// .NET: Program.cs (วางก่อน middleware อื่น)
builder.Services.Configure<ForwardedHeadersOptions>(o =>
{
    o.ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto;
    o.KnownIPNetworks.Clear();   // ตั้งเป็น network ของ proxy ใน production
    o.KnownProxies.Clear();
});

app.UseForwardedHeaders();

ไม่ตั้ง → Request.Scheme เป็น http และ UseHttpsRedirection redirect วนไม่จบ

Checklist Reverse Proxy & HTTPS

  • ☐ ทุกโดเมนเป็น HTTPS · HTTP redirect ไป HTTPS
  • ☐ certificate ต่ออายุอัตโนมัติ (อย่าต่อมือ) + แจ้งเตือนก่อนหมดอายุ
  • ☐ แอปไม่ publish port ออกภายนอก ผ่าน proxy เท่านั้น
  • ☐ แอปอ่าน X-Forwarded-* ถูกต้อง
  • ☐ จำกัดขนาด upload และ timeout เหมาะกับงาน
  • ☐ เปิด compression · cache ไฟล์ static
  • ☐ security headers (HSTS, X-Content-Type-Options)
  • ☐ ทดสอบด้วย SSL Labs ได้เกรด A
