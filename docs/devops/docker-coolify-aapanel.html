Rollback Strategy (การย้อนกลับเวอร์ชัน)

Rollback ระหว่าง Docker แบบทั่วไป กับ Coolify นั้นมีความแตกต่างกันอย่างสิ้นเชิงในเชิง "สถาปัตยกรรม" และ "ความเสี่ยง"

ตารางเปรียบเทียบ Rollback

คุณสมบัติ Docker ทั่วไป (Manual) Self-hosted PaaS
ความง่าย ยาก (ต้องแก้ไฟล์ Config + รันคำสั่ง) ง่าย (คลิกเลือกเวอร์ชันใน UI)
ความเร็ว ช้า (ต้องแก้คน, อาจต้อง Pull image ใหม่) เร็ว (ใช้ Image เดิมที่แคชไว้)
ความเสี่ยง สูง (Human Error, Config ผิด) ต่ำ (ระบบจัดการให้)
Downtime มี (ช่วง Restart container) น้อยมาก (Coolify จัดการ Flow ให้)

Docker แบบทั่วไป (The "Manual" Way)

กลไกทางเทคนิค

  • Image Tagging คือหัวใจ: ถ้าคุณ Deploy โดยใช้ tag ว่า latest ตลอด (เช่น myapp:latest) คุณจะ Rollback ไม่ได้เลย เพราะ Image เก่าถูกทับไปแล้ว
  • วิธีที่ถูก: คุณต้อง Tag ทุกเวอร์ชัน เช่น myapp:v1, myapp:v2

Process การ Rollback

  1. แก้ไฟล์ docker-compose.yml เปลี่ยนจาก image: myapp:v2 กลับเป็น image: myapp:v1
  2. รันคำสั่ง docker compose up -d
  3. Docker จะหยุด Container ตัวปัจจุบัน (v2) -> ลบ Container -> สร้าง Container ใหม่จาก Image v1 -> Start

จุดตาย (Pain Points)

  • Downtime: มีช่วงเวลาที่เว็บเข้าไม่ได้ (Gap) ระหว่าง Stop ตัวเก่าและ Start ตัวใหม่
  • Config Drift: ถ้าแก้ .env แล้วไม่ได้ backup ของเก่า พอ Rollback โค้ดกลับไป แต่ Config เป็นของใหม่... พังครับ
  • Human Error: ต้องพิมพ์คำสั่งเอง ต้องจำ Tag เอง ถ้าจำผิดชีวิตเปลี่ยน

Coolify (The "Snapshot" Way)

Coolify จัดการในระดับ Application Lifecycle Management มองเป็น "Deployment History"

กลไกทางเทคนิค

  • Commit-Based Tracking: ผูกติดกับ Git ทุกครั้งที่ Deploy จะบันทึก Commit Hash ไว้
  • Image Retention: เก็บ Image ของการ Deploy ครั้งก่อนๆ ไว้ ทำให้ไม่ต้อง Build ใหม่

One-Click Rollback

  1. เข้าไปดูประวัติการ Deploy (Deployment History)
  2. เลือกเวอร์ชันเก่าที่ขึ้นสถานะว่า "Success"
  3. กด "Redeploy" หรือ "Rollback"
  4. Coolify จะหยิบ Image หรือ Code ชุดนั้นมา Deploy ทับทันที

ข้อได้เปรียบเชิงลึก

  • Context Aware: รู้ว่า Commit ไหน คู่กับ Config แบบไหน
  • Automated Proxy Switching: Rollback เสร็จแล้วจะสั่ง Traefik สลับ Traffic ให้เองอัตโนมัติ

⚠️ เรื่องใหญ่ที่ต้องระวัง (Database Migration)

ไม่ว่าคุณจะใช้ Coolify หรือ Docker ธรรมดา สิ่งหนึ่งที่ Rollback ไม่ได้คือ Database (ข้อมูล)

สถานการณ์สมมติ

  • V1: มีตาราง Users (name, email)
  • V2: คุณแก้โค้ด และสั่ง Database Migration ลบคอลัมน์ email ทิ้ง
  • App พัง: คุณสั่ง Rollback กลับไป V1
  • ผลลัพธ์: App V1 จะพังทันทีที่ Start เพราะโค้ด V1 หาคอลัมน์ email ไม่เจอ (ถูกลบไปแล้วใน V2)

ทางแก้

  • Docker/Coolify: ช่วยได้แค่เรื่อง Code (App Logic)
  • Database: ต้องมีระบบ Backup/Restore หรือเขียน Script "Down Migration" ไว้เสมอ นี่คือจุดที่ DevOps ต้องเข้ามาดูแล

Multi-Node Management

จุดตัดสำคัญระหว่าง "Enterprise Grade" และ "Hobby Grade"

สำหรับ Head of Dev: "ถ้าพรุ่งนี้ User เข้ามาถล่มจน Server รับไม่ไหว เราจะขยาย (Scale) ไปเครื่องที่ 2, 3, 4 ได้เร็วแค่ไหน?"

เรามาดูการเปรียบเทียบเชิงลึกของ 3 สถาปัตยกรรม

1. aaPanel: "Islands Architecture" (บ้านใครบ้านมัน) 🏝️

aaPanel ไม่ได้ถูกออกแบบมาให้ทำ Cluster หรือ Multi-Node

วิธีการ

  • ถ้ามี 3 Servers ต้องติดตั้ง aaPanel 3 ครั้ง (แยก IP)
  • ต้อง Login เข้า 3 หน้าต่าง (Tab) เพื่อจัดการ

ปัญหาใหญ่ (Pain Points)

  • No Centralized View: ไม่เห็นภาพรวมว่าเครื่องไหนโหลดหนัก เครื่องไหนว่าง
  • No Auto-Sync: ถ้าแก้ Config Nginx เครื่อง 1 ต้องก๊อปไปแก้ที่เครื่อง 2 และ 3 เอง (Manual Sync)
  • Database แยกกัน: การทำ Database Replication ข้ามเครื่องเป็นเรื่องยากและต้องทำมือ

2. Oracle (Manual Docker Swarm / K8s): "The Mesh" 🕸️

วิธีที่ "ถูกต้องตามหลักการ" แต่ "ซับซ้อนมหาศาล"

วิธีการ (Docker Swarm)

  • รันคำสั่ง docker swarm init ที่เครื่องแม่ และ docker swarm join ที่เครื่องลูก
  • สร้าง Overlay Network เพื่อให้ Container ข้ามเครื่องคุยกันได้

ข้อดี

  • High Availability (HA): ถ้าเครื่อง 1 ดับ Container จะย้ายไปเกิดใหม่ที่เครื่อง 2 อัตโนมัติ

ข้อเสีย (High Toil)

  • Learning Curve นรกแตก: ต้องรู้เรื่อง Raft Consensus, Overlay Networking, Ingress Routing
  • Troubleshooting ยาก: เวลาระบบ Network มีปัญหา การหาจุดตาย (Debug) ยากมาก

3. Coolify: "Hub & Spoke" (ศูนย์บัญชาการ) 🎡 🏆

ใช้วิธีฉลาดกว่าคือ "Remote Docker over SSH"

วิธีการ

  1. ติดตั้ง Coolify บนเครื่องหลัก (Control Plane)
  2. เพิ่ม Server ลูก (Worker Nodes) เข้ามาผ่าน SSH Key
  3. จบ! Coolify จะเข้าไปลง Docker Engine ให้เอง และควบคุมจากหน้าจอเดียว

ความเทพ (Killer Features)

  • Single Dashboard: เห็น CPU/RAM/Disk ของทั้ง 10 เครื่อง ในหน้าจอเดียว
  • Deployment Target: มีเมนู Dropdown เลือกได้ว่า "จะลงที่เครื่องไหน?" (เช่น App ลง Server A, DB ลง Server B)
  • Load Balancing (Built-in): จัดการ Routing ภายในเครื่องให้ ส่วนข้ามเครื่องแค่ตั้ง Cloudflare/LB ชี้มาที่ IP ทั้งหมด
