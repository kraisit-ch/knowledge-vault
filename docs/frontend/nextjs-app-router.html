Core Concept

Server Component vs Client Component

🖥️

Server Component ค่าเริ่มต้น

  • รันบน server เท่านั้น ไม่ส่ง JS ไป browser
  • เรียก DB / API / secret ได้ตรง ๆ
  • ใช้ async/await ใน component ได้
  • ใช้ useState, onClick, window ไม่ได้
🖱️

Client Component "use client"

  • มี state, event, effect, browser API
  • ถูก render ครั้งแรกบน server แล้ว hydrate ที่ browser
  • ทุกอย่างที่ import เข้ามาจะถูกส่งไป browser ด้วย
  • ห้ามใส่ secret / connection string
page.tsxServer
→
ProductListServer · ดึงข้อมูล
→
AddToCartButtonClient · onClick
Pattern

ดัน "use client" ลงไปให้ลึกที่สุด

ทั้งหน้าเป็น Client

"use client";
export default function ProductPage() {
  const [qty, setQty] = useState(1);
  const { data } = useQuery(...); // ดึงข้อมูลฝั่ง client
  return <Layout>...</Layout>;   // JS ทั้งหน้าถูกส่งไป
}

หน้าเป็น Server, ปุ่มเป็น Client

// app/products/[id]/page.tsx (Server)
export default async function ProductPage(
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const product = await getProduct(id);
  return (
    <>
      <ProductDetail product={product} />
      <AddToCart productId={product.id} /> {/* "use client" */}
    </>
  );
}
Client Component รับ Server Component เป็น children ได้ เช่น Modal (client) ห่อเนื้อหาที่ render บน server

Data

ดึงข้อมูลจาก .NET API บน Server

// lib/api.ts — ใช้เฉพาะฝั่ง server
import "server-only";

export async function getProducts(category?: string) {
  const res = await fetch(`${process.env.API_URL}/api/products?category=${category ?? ""}`, {
    headers: { Authorization: `Bearer ${await getServiceToken()}` },
    next: { revalidate: 60, tags: ["products"] }, // cache 60 วินาที + ติด tag
  });
  if (!res.ok) throw new Error(`GET /products failed: ${res.status}`);
  return (await res.json()) as Product[];
}

ไม่ cache

cache: "no-store" ข้อมูลส่วนตัว/real-time

cache ตามเวลา

next: { revalidate: 60 }

ล้าง cache ตามเหตุการณ์

revalidateTag("products") หลังบันทึก

ตั้งแต่ Next.js 15 fetch ไม่ cache เป็นค่าเริ่มต้น ต้องระบุเองเสมอ เพื่อให้พฤติกรรมชัดเจน
Mutations

บันทึกข้อมูลด้วย Server Actions

// app/products/actions.ts
"use server";

export async function createProduct(_: State, formData: FormData) {
  const parsed = schema.safeParse(Object.fromEntries(formData));
  if (!parsed.success) return { errors: parsed.error.flatten().fieldErrors };

  const session = await auth();            // ตรวจสิทธิ์ทุกครั้ง!
  if (!session) return { message: "Unauthorized" };

  await api.post("/products", parsed.data);
  revalidateTag("products");
  redirect("/products");
}

// app/products/new/form.tsx
"use client";

export function ProductForm() {
  const [state, action, pending] =
    useActionState(createProduct, {});
  return (
    <form action={action}>
      <input name="name" />
      {state.errors?.name && <p>{state.errors.name}</p>}
      <button disabled={pending}>บันทึก</button>
    </form>
  );
}
สำคัญ: Server Action คือ public endpoint ที่ใครก็ POST มาได้ ต้อง validate input และตรวจสิทธิ์ทุกครั้ง เหมือน API ทั่วไป

File Conventions

ไฟล์พิเศษใน App Router

app/
├─ layout.tsx            # layout หลัก + providers
├─ page.tsx              # หน้าแรก "/"
├─ (marketing)/          # route group ไม่มีผลกับ URL
│  └─ about/page.tsx
├─ (app)/
│  ├─ layout.tsx         # layout หลัง login
│  └─ orders/
│     ├─ page.tsx        # /orders
│     ├─ loading.tsx     # skeleton ระหว่างโหลด
│     ├─ error.tsx       # error boundary
│     ├─ [id]/page.tsx   # /orders/123
│     └─ actions.ts      # server actions
├─ api/webhook/route.ts  # Route Handler (REST)
└─ not-found.tsx

loading.tsx

แสดงทันทีระหว่างรอข้อมูล (Suspense อัตโนมัติ)

error.tsx

ต้องเป็น Client Component, มีปุ่ม reset()

route.ts

ใช้เมื่อต้องการ endpoint จริง เช่น webhook, ไฟล์ download

proxy.ts (เดิม middleware.ts)

redirect ตาม auth / locale ก่อนเข้าหน้า (Next.js 16 เปลี่ยนชื่อเป็น proxy)

Config & Security

Environment Variables: อะไรหลุดไป browser ได้

NEXT_PUBLIC_*

ถูกฝังลง JS ฝั่ง browser ตอน build ใครก็อ่านได้

NEXT_PUBLIC_SITE_URL=https://app.example.com
NEXT_PUBLIC_GA_ID=G-XXXX

ไม่มี prefix

อ่านได้เฉพาะ server (Server Component / Action / Route)

API_URL=http://api.internal:8080
API_CLIENT_SECRET=***
DATABASE_URL=***
  • commit เฉพาะ .env.example ห้าม commit .env.local
  • ใส่ import "server-only" ในไฟล์ที่แตะ secret เพื่อให้ build error ถ้าเผลอ import ฝั่ง client
  • validate env ตอนเริ่มแอปด้วย Zod เพื่อให้พังเร็วถ้าตั้งค่าขาด

// app/products/[id]/page.tsx
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { id } = await params;

Pitfalls

ข้อผิดพลาดที่ทีมเจอบ่อย

Hydration mismatch

render ค่าที่ server/client ต่างกัน เช่น new Date(), Math.random(), window → ย้ายไปใน useEffect หรือส่งค่าจาก server

ใส่ "use client" ที่ layout

ทำให้ทั้งแอปกลายเป็น client → แยก Providers ออกเป็นไฟล์เล็ก

Waterfall request

await a(); await b(); ที่ไม่เกี่ยวกัน → ใช้ Promise.all

เรียก Route Handler ของตัวเองจาก Server Component

เรียกฟังก์ชันตรง ๆ แทน ไม่ต้องวนผ่าน HTTP

ลืมว่า params เป็น Promise

Next.js 15+ ต้อง await params / await searchParams

ไม่ตรวจสิทธิ์ใน Server Action

การซ่อนปุ่มไม่ใช่ security ต้องเช็คที่ server ทุกครั้ง

Deployment

Deploy แบบ Self-host ด้วย Docker

// next.config.ts
const config: NextConfig = {
  output: "standalone",   // ได้ server.js + node_modules ที่จำเป็น
  images: { remotePatterns: [{ hostname: "cdn.example.com" }] },
};
export default config;
  1. build เป็น standalone แล้วใช้ multi-stage Dockerfile (image ~150MB)
  2. ตั้ง env ฝั่ง server ใน runtime, ส่วน NEXT_PUBLIC_* ต้องมีตอน build
  3. วางหลัง reverse proxy (Nginx / Traefik / Coolify) พร้อม HTTPS
  4. ถ้ามีหลาย instance ต้องแชร์ cache (เช่น Redis cache handler)
Summary

สรุป: ถามตัวเองก่อนเขียน

คำถามถ้าใช่ → ทำแบบนี้
