ปัญหาที่แก้

ทำไมทีมต้องใช้ Docker

ไม่มี Docker

  • คนใหม่ใช้ 1–2 วันติดตั้ง Node, .NET SDK, PostgreSQL, Redis
  • เครื่องแต่ละคนเวอร์ชันไม่ตรงกัน → bug เฉพาะเครื่อง
  • Server production ตั้งค่าไม่เหมือนเครื่อง dev

มี Docker

  • docker compose up คำสั่งเดียว ได้ระบบครบทั้งชุด
  • ทุกคนใช้เวอร์ชันเดียวกันตามที่เขียนไว้ในไฟล์
  • image ที่ทดสอบผ่าน คือ image เดียวกับที่ขึ้น production
Docker ไม่ใช่ Virtual Machine: container ใช้ kernel ร่วมกับเครื่องหลัก จึงเปิดเร็วเป็นวินาทีและกินทรัพยากรน้อยกว่ามาก

Image vs Container

Dockerfileสูตรอาหาร
— build →
Imageอาหารแช่แข็ง (อ่านอย่างเดียว)
— run →
Containerอาหารที่อุ่นแล้วกำลังกิน

Image

แม่แบบที่มี OS ย่อ + runtime + โค้ด แก้ไขไม่ได้

ตัวอย่าง: postgres:17, node:22-alpine

Container

สิ่งที่รันอยู่จริงจาก image 1 image รันได้หลาย container

ลบ container แล้ว ข้อมูลข้างในหายด้วย (ถ้าไม่ใช้ volume)

Registry

ที่เก็บ image ให้ดาวน์โหลด

Docker Hub, GitHub Container Registry (ghcr.io)

อ่านชื่อ Image ให้เป็น

ชื่อ Image = registry/ชื่อ:tag

ghcr.io/mercent/order-api:1.4.2
└──┬──┘ └──┬──┘ └───┬───┘ └─┬─┘
registry  owner   ชื่อ image  tag (เวอร์ชัน)

postgres:17-alpine     → Docker Hub (ไม่ระบุ registry), tag = 17-alpine
node:22                → ไม่ใช่ alpine (ใหญ่กว่า แต่เข้ากันได้ดีกว่า)
nginx                  → ไม่ใส่ tag = latest

ห้ามพึ่ง latest

วันนี้กับพรุ่งนี้อาจได้คนละเวอร์ชัน ระบุ tag เสมอ

-alpine

เล็กมาก (~5MB base) แต่ใช้ musl อาจมีปัญหากับ native library บางตัว

-slim

Debian ตัดของไม่จำเป็นออก เป็นตัวเลือกกลางที่ปลอดภัย

ลงมือ

คำสั่งแรก: docker run

docker run -d --name pg -p 5432:5432 -e POSTGRES_PASSWORD=dev postgres:17-alpine
ส่วนความหมาย
-dรันเบื้องหลัง (detached) คืน terminal ให้ทันที
--name pgตั้งชื่อ ไว้อ้างถึงภายหลัง (ไม่ตั้ง Docker จะสุ่มชื่อให้)
-p 5432:5432port เครื่องเรา : port ใน container
-e KEY=valueส่ง environment variable เข้า container (ละเอียดในตอนที่ 4)
postgres:17-alpineimage ที่ใช้ ถ้าไม่มีในเครื่องจะดาวน์โหลดให้อัตโนมัติ

เพิ่ม --rm เพื่อลบ container อัตโนมัติเมื่อหยุด เหมาะกับการลองของชั่วคราว

Lifecycle

วงจรชีวิตของ Container

created
→ start →
running
→ stop →
exitedข้อมูลยังอยู่
→ rm →
ถูกลบข้อมูลหาย
docker stop pg        # หยุด (ส่ง SIGTERM รอ 10 วินาที แล้วค่อย kill)
docker start pg       # เปิดตัวเดิมขึ้นมาใหม่ ข้อมูลข้างในยังอยู่
docker restart pg
docker rm pg          # ลบ (ต้อง stop ก่อน หรือใช้ -f)
docker rm -f pg       # บังคับหยุดและลบทันที
container ถูกออกแบบให้ “ทิ้งได้” ข้อมูลที่ต้องเก็บ เช่น ฐานข้อมูล ต้องอยู่ใน volume (ตอนที่ 5)
ตรวจสอบ

ดูว่าอะไรรันอยู่ และเกิดอะไรขึ้น

docker ps              # container ที่กำลังรัน
docker ps -a           # รวมตัวที่หยุดแล้ว
docker images          # image ในเครื่อง

docker logs pg         # log ทั้งหมด
docker logs -f pg      # ติดตาม log แบบ real-time
docker logs --tail 100 -f pg

docker stats           # CPU / RAM ของแต่ละ container
docker inspect pg      # รายละเอียดทั้งหมด (IP, env, mount)

container หยุดเองทันที?

ดู docker ps -a ช่อง STATUS เช่น Exited (1) แล้ว docker logs หา error

Exit code ที่เจอบ่อย

0 จบปกติ · 1 แอป error · 137 ถูก kill (มักเพราะ RAM ไม่พอ) · 143 ถูกสั่ง stop

Debug

เข้าไปข้างใน Container ด้วย docker exec

docker exec -it pg sh                      # เปิด shell (alpine ใช้ sh, debian ใช้ bash)
docker exec -it pg psql -U postgres        # รันคำสั่งเดียวโดยตรง
docker exec pg env                         # ดู environment variables ที่ container เห็น

docker cp pg:/var/lib/postgresql/data/postgresql.conf ./   # copy ไฟล์ออกมา
docker cp ./seed.sql pg:/tmp/seed.sql                       # copy ไฟล์เข้าไป

-it คืออะไร

-i รับ input จาก keyboard · -t จำลอง terminal ใช้คู่กันเมื่อต้องพิมพ์โต้ตอบ

อย่าแก้ไฟล์ใน container เพื่อแก้ปัญหาถาวร

ลบ container แล้วหายหมด ให้แก้ที่ Dockerfile / config แล้ว build ใหม่

Housekeeping

Docker กินพื้นที่ดิสก์ — ทำความสะอาดเป็นระยะ

docker system df                 # ดูว่าอะไรใช้พื้นที่เท่าไร
docker container prune           # ลบ container ที่หยุดแล้ว
docker image prune               # ลบ image ที่ไม่มีชื่อ (dangling)
docker image prune -a            # ลบ image ที่ไม่มี container ใช้เลย
docker builder prune             # ล้าง build cache
docker system prune              # ลบทั้งหมดข้างบน (ยกเว้น volume)
docker system prune --volumes และ docker volume prune ลบข้อมูลฐานข้อมูลใน volume ด้วย ใช้เมื่อแน่ใจเท่านั้น
