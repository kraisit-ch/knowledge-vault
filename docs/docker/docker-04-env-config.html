.env และ Config
ค่าไปถึงแอปได้อย่างไร

ตอบคำถามที่ทีมเจอบ่อยที่สุด: ทำไมตั้งค่าใน .env แล้วแอปไม่เห็น, ค่าไหนชนะเมื่อตั้งหลายที่, NEXT_PUBLIC_* ทำไมเปลี่ยนไม่ได้ และเก็บรหัสผ่านอย่างไรให้ปลอดภัย

.envenv_fileenvironmentARG vs ENVSecrets
กฎข้อเดียวที่ต้องจำ: config อยู่นอก image, secret อยู่นอก Git
ภาพรวมที่ต้องเข้าใจก่อน

ค่า env ถูกใช้ใน 2 จังหวะ ที่ต่างกัน

ไฟล์ .envข้าง compose.yaml
→ ① แทนค่า ${VAR} →
compose.yamlที่แทนค่าแล้ว
→ ② ส่งเข้า container →
แอปอ่านprocess.env / IConfiguration

① Interpolation

Compose อ่าน .env เพื่อ เติมค่าในไฟล์ compose.yaml

ค่าจาก .env ไม่ได้เข้า container อัตโนมัติ

② Container Environment

ค่าที่แอป เห็นจริง มาจาก environment: และ env_file: เท่านั้น

เช็คด้วย docker compose exec api env

จังหวะ ① Interpolation

.env ข้าง compose.yaml ใช้ “เติมค่าในไฟล์”

# .env  (อยู่โฟลเดอร์เดียวกับ compose.yaml)
DB_PASSWORD=dev-only-pass
API_PORT=8080
POSTGRES_TAG=17-alpine

services:
  db:
    image: postgres:${POSTGRES_TAG}
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}   # ✅ ส่งเข้า container เพราะเขียนไว้ตรงนี้
  api:
    ports: ["${API_PORT}:8080"]
    # API_PORT ใช้แค่เติม ports — container api ไม่เห็นตัวแปรนี้
รูปแบบความหมาย
${VAR}แทนด้วยค่า ถ้าไม่มีได้ค่าว่างพร้อม warning
${VAR:-default}ถ้าไม่มีหรือว่าง ใช้ default
${VAR:?ต้องตั้ง DB_PASSWORD}ถ้าไม่มี หยุดทำงานพร้อมข้อความ error — เหมาะกับค่าบังคับ
$$ใส่เครื่องหมาย $ จริง ๆ (ไม่ให้ถูกแทนค่า)
จังหวะ ② ส่งเข้า Container

environment: vs env_file:

environment:

api:
  environment:
    ASPNETCORE_ENVIRONMENT: Development
    ConnectionStrings__Default: Host=db;Password=${DB_PASSWORD}

เห็นชัดในไฟล์ compose ใช้กับค่าไม่กี่ตัว หรือค่าที่ประกอบจากตัวแปรอื่น

env_file:

api:
  env_file:
    - path: ./env/api.env
      required: true
    - path: ./env/api.local.env   # ค่าเฉพาะเครื่องตัวเอง
      required: false             # ไม่มีไฟล์ก็ไม่ error

โหลด ทุกตัวแปรในไฟล์เข้า container ใช้กับค่าจำนวนมากแยกตาม service

หลักทีม: ค่าที่ไม่ลับและเหมือนกันทุกคน → environment: · ค่าที่เยอะหรือต่างกันแต่ละเครื่อง → env_file:
ตั้งหลายที่ ค่าไหนชนะ?

ลำดับความสำคัญ (บนสุด = ชนะ)

ค่าที่ container ได้รับ

  1. docker compose run -e KEY=...
  2. environment: ใน compose.yaml
  3. env_file:
  4. ENV ใน Dockerfile (ค่าเริ่มต้นใน image)

ค่าที่ใช้แทน ${VAR}

  1. ตัวแปรใน shell / terminal ตอนรันคำสั่ง
  2. ไฟล์ที่ระบุด้วย --env-file
  3. ไฟล์ .env ข้าง compose.yaml
  4. ค่า default ใน ${VAR:-default}
กับดักบ่อย: เคย export DB_PASSWORD=... ไว้ใน terminal แล้วลืม → ค่าใน .env ถูกทับเงียบ ๆ ตรวจด้วย docker compose config
ARG vs ENV

ค่าตอน build กับค่าตอน run ไม่เหมือนกัน

ARG (build-time)ENV / environment (runtime)
ส่งด้วย--build-arg / build.args-e / environment: / env_file:
ใช้ได้ตอนคำสั่ง RUN ใน Dockerfile เท่านั้นตอนแอปทำงาน
เปลี่ยนค่าต้อง build image ใหม่แค่ restart container
เหมาะกับเวอร์ชัน, ค่าที่ต้องฝังในไฟล์ buildURL, connection string, feature flag
ใส่ secret ได้ไหมไม่ได้ — ดูได้จาก docker historyได้ แต่ควรใช้ secret แทน (สไลด์ 11)
image เดียวควรใช้ได้ทุก environment (dev / staging / prod) ต่างกันแค่ค่าที่ส่งตอน run
Next.js

NEXT_PUBLIC_* ถูกฝังตอน build

ปัญหา

NEXT_PUBLIC_API_URL ถูกแทนเป็นข้อความตรง ๆ ใน JS ตอน npm run build

ตั้งค่าตอน docker run จะ ไม่มีผล กับฝั่ง browser → ได้ URL ของ dev ไปขึ้น production

ค่าที่ไม่มี prefix

API_URL, AUTH_SECRET อ่านตอน runtime ฝั่ง server ได้ปกติ

เปลี่ยนค่าตอน run ได้ ไม่ต้อง build ใหม่

ทางแก้ (เลือก 1)

1. ลดการใช้ NEXT_PUBLIC แนะนำ

ให้ Server Component / Route Handler เรียก API ด้วย API_URL แล้วส่งข้อมูลให้ client

2. Build แยกต่อ environment

ส่ง --build-arg NEXT_PUBLIC_... ต่างกัน ได้ image แยก web:1.4-staging / web:1.4-prod

3. ส่ง config จาก server

อ่าน env ใน root layout (server) แล้วส่งผ่าน Context ให้ client component ใช้

.NET / ASP.NET Core

.NET อ่าน env อย่างไร: ใช้ __ แทน :

// appsettings.json

  "ConnectionStrings": { "Default": "Host=localhost;..." },

Team Standard

โครงสร้างไฟล์ env ที่ทีมใช้

project/
├── compose.yaml
├── compose.override.yaml     # dev
├── .env.example              ✅ commit  (ตัวอย่าง, ไม่มีค่าจริง)
├── .env                      ❌ ห้าม commit (ค่าของเครื่องเรา)
└── env/
    ├── api.env.example       ✅ commit
    ├── api.env               ❌ ห้าม commit
    ├── web.env.example       ✅ commit
    └── web.env               ❌ ห้าม commit

# .env.example — ทุก key ที่ต้องมี + คำอธิบาย
# รหัสผ่าน DB สำหรับเครื่อง dev (ตั้งอะไรก็ได้)
DB_PASSWORD=
# port ของ API บนเครื่องเรา
API_PORT=8080
  1. คนใหม่: cp .env.example .env และ cp env/api.env.example env/api.env แล้วเติมค่า
  2. เพิ่มตัวแปรใหม่: อัปเดต *.example ใน PR เดียวกันเสมอ และแจ้งทีม

🚨 ถ้าเผลอ commit / push secret

  1. เปลี่ยนรหัส/คีย์นั้นทันที (rotate) — สำคัญที่สุด
  2. ลบไฟล์ออกจาก Git และเพิ่มใน .gitignore
  3. แจ้งหัวหน้าทีม

การลบ commit ไม่พอ เพราะประวัติ Git ถูก clone / cache ไปแล้ว ถือว่ารหัสนั้นรั่วไปแล้ว

เก็บรหัสผ่านให้ปลอดภัย

Secret ไม่ควรอยู่ใน env ถ้าเลี่ยงได้

Runtime secret: Compose secrets

services:
  db:
    image: postgres:17-alpine
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password
    secrets: [db_password]
secrets:
  db_password:
    file: ./secrets/db_password.txt

ไฟล์ถูก mount ที่ /run/secrets/ ไม่โผล่ใน docker inspect · .NET อ่านได้ด้วย AddKeyPerFile("/run/secrets")

Build secret: ไม่ฝังลง image

RUN --mount=type=secret,id=npmrc,target=/root/.npmrc npm ci

docker build --secret id=npmrc,src=$HOME/.npmrc .

ใช้กับ token ของ private registry ตอนติดตั้ง package แทน ARG NPM_TOKEN

Production บน Coolify / cloud: ตั้งค่า secret ผ่านหน้าจัดการ environment ของแพลตฟอร์ม หรือ Key Vault แทนการวางไฟล์บน server
Debug

ค่าไม่ตรงที่คิด? ตรวจตามลำดับนี้

  1. docker compose config — ดูไฟล์หลังแทนค่า ${VAR} แล้ว ค่าถูกไหม?
  2. docker compose exec api env | sort — container เห็นค่าอะไรจริง ๆ?
  3. แก้ .env แล้ว ใช้ docker compose up -d (สร้าง container ใหม่) — restart ไม่โหลดค่าใหม่
  4. เป็น NEXT_PUBLIC_* หรือ ARG? → ต้อง up -d --build
  5. แอป validate config ตอนเริ่ม: Zod (Next.js) / ValidateOnStart() (.NET) ค่าผิดต้องพังทันทีพร้อมบอกชื่อตัวแปร
Pitfalls

ข้อผิดพลาดที่พบบ่อย

ใส่ใน .env แล้วคิดว่าแอปเห็น

.env ใช้แทนค่าในไฟล์ compose ต้องส่งต่อผ่าน environment: หรือ env_file:

เว้นวรรครอบ =

KEY = value ผิด ต้องเป็น KEY=value

คอมเมนต์ท้ายบรรทัด / quote ซ้อน

เขียนคอมเมนต์บรรทัดของตัวเอง และใส่ quote เมื่อค่ามีช่องว่างหรือ #

ไฟล์ .env เป็น CRLF (Windows)

ค่ามี \r ติดท้าย รหัสผ่านผิดโดยมองไม่เห็น ตั้ง editor เป็น LF

ใช้ localhost ใน connection string

ใน container ต้องใช้ชื่อ service เช่น Host=db

secret ใน ARG / ENV ของ Dockerfile

ติดไปกับ image อ่านได้ด้วย docker history / inspect

สรุป

Checklist การจัดการ env

  • ☐ มี .env.example ครบทุก key พร้อมคำอธิบาย
  • ☐ .env อยู่ใน .gitignore และ .dockerignore
  • ☐ ค่าบังคับใช้ ${VAR:?message}
  • ☐ image เดียวใช้ได้ทุก environment
  • ☐ แยก NEXT_PUBLIC_* (build) ออกจากค่า runtime ชัดเจน
  • ☐ ไม่มี secret ใน Dockerfile, ARG, หรือ Git
  • ☐ production ใช้ secret / ระบบจัดการ env ของแพลตฟอร์ม
  • ☐ แอป validate config ตอนเริ่ม
  • ☐ รู้จัก docker compose config และ exec env
  • ☐ เผลอ commit secret → rotate ทันที
