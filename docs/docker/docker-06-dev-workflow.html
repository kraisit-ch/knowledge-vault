ทีมใช้ได้ทั้งคู่ด้วย profiles: docker compose up -d = infra · docker compose --profile app up -d = รวมแอป

แก้โค้ดแล้วเห็นผลทันที

Compose Watch

services:
  web:
    build: { context: ./web, target: dev }   # stage dev ที่รัน "npm run dev"
    ports: ["3000:3000"]
    develop:
      watch:
        - action: sync              # แก้โค้ด → copy เข้า container
          path: ./web/src
          target: /app/src
        - action: rebuild           # แก้ package.json → build image ใหม่
          path: ./web/package.json

docker compose up --watch      # เปิด + เฝ้าดูไฟล์
# หรือ
docker compose watch
actionเมื่อไฟล์เปลี่ยนใช้กับ
synccopy ไฟล์เข้า container (dev server reload เอง)source code
sync+restartcopy แล้ว restart containerไฟล์ config
rebuildbuild image ใหม่และสร้าง container ใหม่package.json, *.csproj
อีกทางเลือก

Hot Reload ด้วย Bind Mount

services:
  web:
    image: node:22-alpine
    working_dir: /app
    command: sh -c "npm ci && npm run dev"
    volumes:
      - ./web:/app                 # โค้ดบนเครื่อง ↔ container
      - web_node_modules:/app/node_modules   # แยก node_modules ของ Linux
    environment:
      WATCHPACK_POLLING: "true"    # ให้ตรวจจับไฟล์เปลี่ยนบน Windows
    ports: ["3000:3000"]
volumes:
  web_node_modules:

ทำไมต้องแยก node_modules

ไม่ให้ node_modules ของ Windows ทับของ Linux ใน container (native module ใช้ข้ามระบบไม่ได้)

Polling

event แก้ไฟล์จาก Windows ส่งเข้า container ไม่ได้เสมอไป เปิด polling ให้ dev server ตรวจเอง (แลกกับ CPU)

.NET

ใช้ image sdk + dotnet watch run ได้ แต่ debug สะดวกกว่ามากถ้ารัน API บนเครื่อง (รูปแบบ A)

สำหรับเครื่อง Windows

Docker Desktop บน Windows: ตั้งค่าให้ลื่น

1. ใช้ WSL2 backend

Settings → General → Use WSL 2 based engine (ค่าเริ่มต้นแล้ว)

2. ถ้า bind mount ช้า: เก็บโค้ดใน WSL

clone ไว้ที่ \\wsl$\Ubuntu\home\<user>\projects แล้วเปิดด้วย VS Code (WSL) mount จาก C:\ ช้ากว่าหลายเท่า

3. จำกัด RAM ของ WSL

# %UserProfile%\.wslconfig
[wsl2]
memory=8GB
processors=4

แล้วรัน wsl --shutdown เพื่อให้มีผล

4. Line ending (CRLF)

# .gitattributes ที่ root ของ repo
*.sh   text eol=lf
*.env  text eol=lf
Dockerfile text eol=lf

script ที่เป็น CRLF จะ error no such file or directory ทั้งที่ไฟล์มีอยู่

Debug Toolkit

ลำดับการ Debug เมื่อมีปัญหา

  1. docker compose ps — service ไหนไม่ขึ้น / unhealthy / restart วน?
  2. docker compose logs --tail 200 -f api — อ่าน error บรรทัดแรกที่เกิด ไม่ใช่บรรทัดสุดท้าย
  3. docker compose config — ค่าใน compose หลังแทนตัวแปรถูกไหม
  4. docker compose exec api sh แล้ว env, ls, wget -qO- http://db:5432 — ดูจากมุม container
  5. docker inspect <container> — mount, network, IP, exit code, health log
# ทดสอบ network จาก container เครื่องมือครบชุด (curl, dig, nc) แล้วลบทิ้งเมื่อออก
docker run --rm -it --network shop_default nicolaka/netshoot

Error ที่เจอบ่อย และวิธีแก้ (1/2)

อาการ / ข้อความสาเหตุวิธีแก้
port is already allocatedport ฝั่งเครื่องเราถูกใช้อยู่ปิดโปรแกรมนั้น หรือเปลี่ยนเป็น "15432:5432"
Cannot connect to the Docker daemonDocker Desktop ยังไม่เปิดเปิด Docker Desktop รอจนสถานะ Running
API ต่อ DB ไม่ได้ Connection refusedใช้ localhost หรือ DB ยังไม่พร้อมHost=db + depends_on: service_healthy
container ขึ้นแล้วหยุดทันทีแอป error ตอนเริ่ม / config ขาดdocker compose logs api ดูบรรทัดแรกของ error
แก้โค้ดแล้วไม่เปลี่ยนยังรัน image เก่าup -d --build หรือใช้ watch

Error ที่เจอบ่อย และวิธีแก้ (2/2)

อาการ / ข้อความสาเหตุวิธีแก้
exec ./entrypoint.sh: no such file or directoryscript เป็น CRLF (Windows).gitattributes *.sh eol=lf แล้ว checkout ใหม่
permission denied เขียนไฟล์ใน volumecontainer รันเป็น non-root แต่โฟลเดอร์เป็นของ rootCOPY --chown= / สร้างโฟลเดอร์และ chown ใน Dockerfile
Exit code 137RAM ไม่พอ (OOM killed)เพิ่ม RAM ให้ WSL/Docker หรือหาจุด memory leak
no space left on deviceimage / cache สะสมdocker system df → docker system prune
build ใช้ cache เก่าผิด ๆcache ไม่ถูก invalidatedocker compose build --no-cache api
แก้ .env แล้วค่าไม่เปลี่ยนใช้ restartdocker compose up -d (สร้าง container ใหม่)
