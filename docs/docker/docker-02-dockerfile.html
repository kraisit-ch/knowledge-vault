ทำให้ Build เร็ว

Layer Cache: ลำดับคำสั่งมีผลมาก

copy ทุกอย่างก่อน install

FROM node:22-alpine
WORKDIR /app
# แก้โค้ด 1 บรรทัด
COPY . .
# → ติดตั้ง package ใหม่ทุกครั้ง (ช้า)
RUN npm ci
RUN npm run build

copy ไฟล์ dependency ก่อน

FROM node:22-alpine
WORKDIR /app
COPY package.json package-lock.json ./
# cache ไว้ จนกว่า lock file จะเปลี่ยน
RUN npm ci
# แก้โค้ด → build ใหม่แค่จากตรงนี้
COPY . .
RUN npm run build
เรียงจาก “เปลี่ยนน้อย” ไป “เปลี่ยนบ่อย” — ถ้า layer ไหนเปลี่ยน ทุก layer หลังจากนั้นต้อง build ใหม่

ตัวอย่างจริง · Next.js

Dockerfile สำหรับ Next.js (standalone)

HOSTNAME=0.0.0.0 จำเป็น ไม่งั้น server ฟังแค่ใน container เอง เข้าจากข้างนอกไม่ได้

FROM node:22-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

FROM node:22-alpine AS build
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
# ค่า NEXT_PUBLIC_* ต้องมีตอน build (ดูตอนที่ 4)
ARG NEXT_PUBLIC_API_URL
ENV NEXT_PUBLIC_API_URL=$NEXT_PUBLIC_API_URL
# next.config: output: "standalone"
RUN npm run build

FROM node:22-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production PORT=3000 HOSTNAME=0.0.0.0
COPY --from=build --chown=node:node /app/.next/standalone ./
COPY --from=build --chown=node:node /app/.next/static ./.next/static
COPY --from=build --chown=node:node /app/public ./public
USER node
EXPOSE 3000
CMD ["node", "server.js"]
ตัวอย่างจริง · .NET

Dockerfile สำหรับ ASP.NET Core Web API

ใช้ sdk สำหรับ build และ aspnet (เล็กกว่ามาก) สำหรับรัน · เปลี่ยนเวอร์ชันให้ตรงกับ TargetFramework ของโปรเจกต์

FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
# copy เฉพาะไฟล์โปรเจกต์ก่อน เพื่อ cache ขั้น restore
COPY Shop.sln Directory.Packages.props ./
COPY src/Shop.Api/Shop.Api.csproj src/Shop.Api/
COPY src/Shop.Application/Shop.Application.csproj src/Shop.Application/
COPY src/Shop.Domain/Shop.Domain.csproj src/Shop.Domain/
COPY src/Shop.Infrastructure/Shop.Infrastructure.csproj src/Shop.Infrastructure/
RUN dotnet restore src/Shop.Api/Shop.Api.csproj

COPY . .
RUN dotnet publish src/Shop.Api/Shop.Api.csproj -c Release -o /app/publish --no-restore

FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .
# user ที่ไม่ใช่ root ซึ่งมีมากับ image ของ Microsoft
USER $APP_UID
# .NET 8+ ฟัง port 8080 เป็นค่าเริ่มต้น
EXPOSE 8080
ENTRYPOINT ["dotnet", "Shop.Api.dll"]

Build และรัน Image ของเรา

# build: -t ตั้งชื่อ:tag, . คือ build context (โฟลเดอร์ที่ส่งให้ Docker)
docker build -t shop-web:dev .
docker build -t shop-api:dev -f src/Shop.Api/Dockerfile .

# ส่ง build arg
docker build -t shop-web:dev --build-arg NEXT_PUBLIC_API_URL=http://localhost:8080 .

# build เฉพาะบาง stage (เช่น ไว้ debug)
docker build --target build -t shop-web:build .

# รัน
docker run --rm -p 3000:3000 shop-web:dev
docker run --rm -p 8080:8080 -e ASPNETCORE_ENVIRONMENT=Development shop-api:dev

# ดูว่าแต่ละ layer ใหญ่แค่ไหน
docker history shop-web:dev
มักสับสน

CMD vs ENTRYPOINT และรูปแบบ exec

CMD

คำสั่งเริ่มต้น ถูกแทนที่ได้ ตอน run

docker run shop-web:dev sh   # รัน sh แทน node server.js

ENTRYPOINT

ตัวโปรแกรมหลัก CMD จะกลายเป็น argument ต่อท้าย

ENTRYPOINT ["dotnet", "Shop.Api.dll"]
CMD ["--urls", "http://+:8080"]

ใช้รูปแบบ JSON (exec form)

CMD ["node", "server.js"]

แอปได้รับสัญญาณ stop โดยตรง ปิดตัวอย่างสุภาพได้

รูปแบบ shell form

CMD node server.js

รันผ่าน sh -c แอปไม่ได้รับ SIGTERM → ถูก kill หลัง 10 วินาที

สรุป

Checklist Dockerfile ที่ดี

  • ☐ ระบุ tag ของ base image ชัดเจน (ไม่ใช้ latest)
  • ☐ copy ไฟล์ dependency ก่อน แล้วค่อย copy โค้ด
  • ☐ มี .dockerignore และ ignore .env
  • ☐ ใช้ multi-stage แยก build กับ runtime
  • ☐ รันด้วย user ที่ไม่ใช่ root (USER)
  • ☐ CMD/ENTRYPOINT แบบ JSON
  • ☐ ไม่มีรหัสผ่านหรือ secret ใน Dockerfile / ARG
  • ☐ เริ่มโปรเจกต์ใหม่ลอง docker init ช่วยสร้างไฟล์ตั้งต้น
