CLI

คำสั่งจัดการ Volume

docker volume ls                       # รายการ volume
docker volume inspect shop_pgdata      # ดูรายละเอียด (ชื่อ = project_volume)
docker volume rm shop_pgdata           # ลบ (ข้อมูลหาย)
docker compose down -v                 # ลบ container + volume ของ project

# รีเซ็ต DB บนเครื่อง dev ให้เริ่มใหม่หมด
docker compose down -v
docker compose up -d

ชื่อ volume จริง

Compose เติมชื่อ project ข้างหน้า เช่น pgdata → shop_pgdata

init script ทำงานครั้งเดียว

ไฟล์ใน /docker-entrypoint-initdb.d ของ Postgres รันเฉพาะตอน volume ว่าง ถ้าแก้ script ต้อง down -v ก่อน

สำรองข้อมูล

Backup & Restore ฐานข้อมูลใน Container

PostgreSQL

# backup → ไฟล์บนเครื่องเรา
docker compose exec -T db pg_dump -U shop -Fc shop > backup.dump

# restore
docker compose exec -T db pg_restore -U shop -d shop --clean < backup.dump

SQL Server

docker compose exec mssql /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U sa -P "$MSSQL_SA_PASSWORD" -C \
  -Q "BACKUP DATABASE Shop TO DISK='/var/opt/mssql/backup/shop.bak'"
docker compose cp mssql:/var/opt/mssql/backup/shop.bak ./
-T ปิดการจำลอง terminal จำเป็นเมื่อส่งข้อมูลผ่าน > หรือ < ไม่งั้นไฟล์ backup จะเสีย
การ copy โฟลเดอร์ volume ขณะ DB กำลังทำงานไม่ใช่ backup ที่เชื่อถือได้ ให้ใช้เครื่องมือของ DB (pg_dump, BACKUP DATABASE) เสมอ

ภายใน network

ใช้ ชื่อ service + port ภายใน (5432) ไม่ใช่ port ที่ map ออกมา

จากเครื่องเรา

ใช้ localhost + port ฝั่งซ้าย ของ ports:

localhost ใน container

หมายถึงตัว container เอง ไม่ใช่เครื่องเรา และไม่ใช่ service อื่น

เปิด port เท่าที่จำเป็น

ports: = เปิดให้นอก Docker เข้าถึง

services:
  web:
    ports: ["3000:3000"]          # ผู้ใช้ต้องเข้าถึง
  api:
    ports: ["127.0.0.1:8080:8080"] # เปิดเฉพาะเครื่องนี้ ไม่เปิดสู่ LAN
  db:
    # ไม่มี ports: → เข้าถึงได้เฉพาะ service ใน network เดียวกัน
    image: postgres:17-alpine

ผูกกับ 127.0.0.1

"8080:8080" เปิดให้ทุกเครื่องในวง LAN/Internet เห็น ถ้าไม่ต้องการให้ใส่ 127.0.0.1: ข้างหน้า

Docker ข้าม firewall (Linux)

port ที่ publish ไม่ถูก ufw บล็อก เพราะ Docker แก้ iptables เอง ระวังบน server จริง

กรณีพิเศษ

Container ต้องเรียกโปรแกรมที่รันบนเครื่องเรา

เช่น รัน .NET API ใน Visual Studio (นอก Docker) แต่ Next.js อยู่ใน container

services:
  web:
    environment:
      API_URL: http://host.docker.internal:5080
    extra_hosts:
      - "host.docker.internal:host-gateway"   # จำเป็นบน Linux (Docker Desktop มีให้อยู่แล้ว)

host.docker.internal

ชื่อพิเศษที่ชี้กลับมาที่เครื่องเรา ใช้ได้ทันทีบน Docker Desktop (Windows/Mac)

แอปบนเครื่องต้องฟัง 0.0.0.0 หรือ interface ที่เข้าถึงได้

ถ้าฟังเฉพาะ localhost บางกรณี container จะเข้าไม่ได้

สรุป

Checklist Volume & Network

  • ☐ DB / Redis / ไฟล์อัปโหลด อยู่ใน named volume
  • ☐ bind mount ใช้กับโค้ดตอน dev และ config แบบ :ro
  • ☐ มีคำสั่ง backup / restore ที่ทดสอบแล้ว
  • ☐ รู้ว่า down -v ลบข้อมูล
  • ☐ service คุยกันด้วยชื่อ service + port ภายใน
  • ☐ ไม่ ports: ให้ DB ใน production
  • ☐ ใช้ 127.0.0.1: เมื่อไม่ต้องเปิดสู่ภายนอก
  • ☐ เรียกเครื่องเราด้วย host.docker.internal
