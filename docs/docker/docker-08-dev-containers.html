เริ่มต้น · Next.js

.devcontainer/devcontainer.json แบบง่ายที่สุด

{
  "name": "Shop Web (Next.js)",
  "image": "mcr.microsoft.com/devcontainers/typescript-node:22",
  "forwardPorts": [3000],
  "postCreateCommand": "npm ci",
  "customizations": {
    "vscode": {
      "extensions": [
        "dbaeumer.vscode-eslint",
        "esbenp.prettier-vscode",
        "bradlc.vscode-tailwindcss"
      ],
      "settings": { "editor.formatOnSave": true }
    }
  }
}
  1. commit ไฟล์นี้ลง repo
  2. เปิดโปรเจกต์ใน VS Code จะมีป้ายเด้งขึ้นมา → Reopen in Container (หรือ F1 → “Dev Containers: Reopen in Container”)
  3. รอสร้างครั้งแรก (ครั้งต่อไปเร็วเพราะมี cache)
  4. เปิด terminal ใน VS Code → npm run dev → เปิด localhost:3000 บนเครื่องได้เลย

image ทางการของทีม Dev Containers อยู่ที่ mcr.microsoft.com/devcontainers/* มี Node, git, zsh และ user ที่ไม่ใช่ root (node / vscode) มาให้แล้ว

Next.js + .NET + PostgreSQL + Redis

Dev Container แบบมี DB และ Redis มาด้วย

// .devcontainer/devcontainer.json
{
  "name": "Shop (Full stack)",
  "dockerComposeFile": ["compose.yaml"],
  "service": "dev",
  "workspaceFolder": "/workspaces/shop",
  "shutdownAction": "stopCompose",
  "features": {
    "ghcr.io/devcontainers/features/node:1": { "version": "22" }
  },
  "forwardPorts": [3000, 8080, "db:5432"],
  "postCreateCommand": "npm ci --prefix web && dotnet restore",
  "customizations": { "vscode": { "extensions": [
    "ms-dotnettools.csdevkit", "dbaeumer.vscode-eslint"
  ] } }
}

# .devcontainer/compose.yaml
services:
  dev:
    image: mcr.microsoft.com/devcontainers/dotnet:10.0
    volumes:
      - ..:/workspaces/shop:cached     # โค้ดทั้ง repo
    command: sleep infinity            # ให้ container อยู่รอ VS Code
    environment:
      ConnectionStrings__Default: Host=db;Database=shop;Username=shop;Password=dev
      Redis__Connection: redis:6379
  db:
    image: postgres:17-alpine
    environment: { POSTGRES_DB: shop, POSTGRES_USER: shop, POSTGRES_PASSWORD: dev }
    volumes: [pgdata:/var/lib/postgresql/data]
  redis:
    image: redis:7-alpine
volumes:
  pgdata:

ในโค้ดเรียก DB ด้วยชื่อ service (Host=db) เหมือนตอนที่ 3 · "db:5432" ใน forwardPorts ทำให้ DBeaver บนเครื่องต่อ localhost:5432 ได้

.NET / C#

พัฒนา .NET ใน Dev Container

Debug ได้ปกติ

  • ติดตั้ง ms-dotnettools.csdevkit ใน customizations
  • F5 / breakpoint / Test Explorer ทำงานใน container
  • dotnet watch สำหรับ hot reload

เรื่องที่ต้องตั้งค่า

  • ให้ Kestrel ฟังทุก interface: ASPNETCORE_URLS=http://+:8080 แล้ว forward 8080
  • HTTPS dev certificate ของเครื่องไม่ติดเข้าไป — ใน dev container ใช้ HTTP ไปก่อน หรือสร้าง cert ใหม่ใน container
  • NuGet cache: mount volume ที่ /home/vscode/.nuget/packages เพื่อไม่ต้องโหลดใหม่ทุกครั้งที่ rebuild
ทีมที่ใช้ Visual Studio (Windows) เป็นหลัก ยังใช้รูปแบบ A (infra ใน Docker, แอปบนเครื่อง) ได้ตามเดิม Dev Container เหมาะกับคนที่ใช้ VS Code / Rider และงาน frontend มากกว่า
เชื่อมกับตอนที่ 4

Environment variable และ Secret ใน Dev Container

{
  // ค่าทั่วไปที่ไม่ลับ: ใส่ตรงนี้ได้
  "containerEnv": {
    "ASPNETCORE_ENVIRONMENT": "Development",
    "NEXT_TELEMETRY_DISABLED": "1"
  },
  // ค่าลับ: ดึงจาก env ของเครื่องเรา ไม่ commit ลง Git
  "remoteEnv": {
    "OPENAI_API_KEY": "${localEnv:OPENAI_API_KEY}"
  },
  // หรือโหลดทั้งไฟล์ (ไฟล์อยู่ใน .gitignore)
  "runArgs": ["--env-file", ".devcontainer/.env"]
}

containerEnv

ตั้งตอนสร้าง container — process ทุกตัวเห็น เปลี่ยนแล้วต้อง rebuild

remoteEnv

ตั้งให้ VS Code / terminal — เปลี่ยนแล้วแค่ reload window

อย่า commit

.devcontainer/.env ต้องอยู่ใน .gitignore และมี .env.example แทน (กฎเดียวกับตอนที่ 4)

runArgs ใช้กับแบบ image / build · ถ้าใช้ Compose ให้ใส่ env_file: ใน compose.yaml แทน

สำหรับเครื่อง Windows

ทำให้ Dev Container บน Windows เร็ว

1. เก็บโค้ดใน container volume หรือ WSL

F1 → “Dev Containers: Clone Repository in Container Volume” โค้ดอยู่ใน volume ของ Docker ไม่ต้องข้าม Windows ↔ Linux จึงเร็วกว่า mount จาก C:\ มาก

2. หรือเปิดจาก WSL

clone ไว้ที่ ~/projects ใน WSL แล้วเปิดด้วย VS Code (WSL) ก่อน แล้วค่อย Reopen in Container

3. Line ending

ใส่ .gitattributes ให้ไฟล์ *.sh เป็น LF (ตอนที่ 6) ไม่งั้น script ใน container error

4. RAM ของ WSL

dev container + DB + Redis + VS Code Server ใช้ RAM รวมหลาย GB ตั้ง .wslconfig ให้พอ

Daily Workflow

ใช้งานประจำวัน: เมื่อไรต้อง Rebuild

สถานการณ์ทำอะไร (F1 → Dev Containers: …)
เปิดโปรเจกต์ครั้งแรก / หลังปิดเครื่องReopen in Container
แก้โค้ด, เพิ่ม npm / NuGet packageไม่ต้องทำอะไร ติดตั้งใน terminal ได้เลย
pull มาแล้ว devcontainer.json, Dockerfile หรือ features เปลี่ยนRebuild Container
container เพี้ยน / cache ผิดRebuild Without Cache
กลับไปทำงานบนเครื่องปกติReopen Folder Locally
ค่าส่วนตัว (theme, font, shell alias) ไม่ต้องใส่ใน devcontainer.json ของทีม ใช้ Settings Sync หรือ dotfiles repo ของตัวเองแทน
Troubleshooting

ปัญหาที่พบบ่อย

อาการสาเหตุวิธีแก้
เปิด localhost:3000 ไม่ได้dev server ฟังแค่ใน containerรันด้วย --hostname 0.0.0.0 / ASPNETCORE_URLS=http://+:8080 และใส่ใน forwardPorts
ไฟล์บนเครื่องเป็นของ root แก้ไม่ได้ทำงานใน container ด้วย rootใช้ image ทางการ + "remoteUser": "node" / "vscode"
แก้ devcontainer.json แล้วไม่เห็นผลยังใช้ container เดิมRebuild Container
build / npm install ช้ามาก (Windows)mount โค้ดจาก C:\Clone in Container Volume / WSL
node_modules ใช้ข้ามเครื่องไม่ได้ติดตั้งบน Windows แล้วเปิดใน Linuxลบแล้ว npm ci ใหม่ใน container (ใส่ใน postCreateCommand)
git push ไม่ได้ / ถามรหัสตลอดcredential ไม่ถูกส่งเข้า containerตั้ง Git Credential Manager / SSH agent บนเครื่องให้ทำงานก่อน
สรุป

ควรใช้เมื่อไร และ Checklist ของทีม

ใช้ Dev Container เมื่อ

  • มีคนเข้าออกทีมบ่อย อยากให้เริ่มงานได้ในวันแรก
  • ต้องใช้หลายเวอร์ชัน (Node 20 กับ 22, .NET 8 กับ 10) ในหลายโปรเจกต์
  • ทีมใช้ VS Code / Rider / Codespaces

ไม่จำเป็นเมื่อ

  • ทีมเล็ก เครื่องเหมือนกันหมดอยู่แล้ว
  • ใช้ Visual Studio บน Windows เป็นหลัก
  • เครื่อง RAM น้อย (< 16GB) และต้องรันหลาย service
  • ☐ .devcontainer/ อยู่ใน Git · image / features ระบุเวอร์ชัน
  • ☐ extension ที่ทีมใช้ร่วม (ESLint, Prettier, C# Dev Kit) อยู่ใน customizations
  • ☐ postCreateCommand ติดตั้ง dependency ให้ครบ · secret มาจาก ${localEnv:…} / .env ที่ไม่ commit
  • ☐ README มีขั้นตอน “Reopen in Container” และทดสอบกับเครื่องใหม่แล้ว
