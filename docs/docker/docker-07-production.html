ตั้ง Tag ให้ย้อนกลับได้เสมอ

# CI สร้าง tag ทั้งเวอร์ชันและ commit
docker build -t ghcr.io/mercent/shop-api:1.4.2 \
             -t ghcr.io/mercent/shop-api:sha-3f9c2a1 .
docker push ghcr.io/mercent/shop-api --all-tags

Immutable tag

1.4.2 และ sha-3f9c2a1 ต้องไม่ถูกเขียนทับ รู้เสมอว่ารันโค้ดอะไร

ห้าม deploy latest

rollback ไม่ได้ และไม่รู้ว่าแต่ละเครื่องรันเวอร์ชันไหน

Rollback = เปลี่ยน tag

แก้ image: ...:1.4.1 แล้ว up -d หรือกด redeploy เวอร์ชันก่อนใน Coolify

ตัวอย่าง

compose.prod.yaml

services:
  api:
    image: ghcr.io/mercent/shop-api:${API_TAG:?ต้องระบุ API_TAG}
    restart: unless-stopped
    env_file: [/srv/shop/api.env]            # อยู่บน server ไม่อยู่ใน Git
    healthcheck:
      test: ["CMD", "curl", "-fsS", "http://localhost:8080/health"]
      interval: 15s
      timeout: 3s
      retries: 3
      start_period: 20s
    deploy:
      resources:
        limits: { cpus: "1.0", memory: 512M }
    logging:
      driver: json-file
      options: { max-size: "10m", max-file: "5" }
    read_only: true
    tmpfs: [/tmp]
    security_opt: ["no-new-privileges:true"]
    cap_drop: [ALL]
    stop_grace_period: 30s
ระบบรู้ว่าแอปพร้อมจริง

Healthcheck: “รันอยู่” ไม่เท่ากับ “พร้อมใช้งาน”

// .NET: Program.cs
builder.Services.AddHealthChecks()
    .AddNpgSql(builder.Configuration.GetConnectionString("Default")!)
    .AddRedis(builder.Configuration["Redis:Connection"]!);

app.MapHealthChecks("/health");

// Next.js: app/api/health/route.ts
export const dynamic = "force-dynamic";
export function GET() {
  return Response.json({ status: "ok" });
}

ใช้ทำอะไร

depends_on รอ, reverse proxy ไม่ส่ง traffic ไปตัวที่ป่วย, Coolify/Swarm restart ตัวที่ป่วย

image ต้องมีเครื่องมือ

image ของ aspnet ไม่มี curl โดยค่าเริ่มต้น ต้องติดตั้งเพิ่ม หรือใช้ healthcheck ฝั่ง proxy แทน

อย่าเช็คหนักเกินไป

health ที่ query DB หนักทุก 5 วินาทีก็สร้างภาระได้

ความปลอดภัย

ลดความเสียหายถ้า container ถูกเจาะ

1. ไม่รันเป็น root

USER node / USER $APP_UID ใน Dockerfile

2. ระบบไฟล์อ่านอย่างเดียว

read_only: true + tmpfs สำหรับโฟลเดอร์ที่ต้องเขียน

3. ตัดสิทธิ์พิเศษของ Linux

cap_drop: [ALL] และ no-new-privileges

4. ใช้ base image เล็กและอัปเดต

-alpine / -slim / chiseled ของ .NET · rebuild เมื่อมี security patch

5. ห้าม mount /var/run/docker.sock

เทียบเท่าให้สิทธิ์ root ของทั้ง server ยกเว้นเครื่องมือที่จำเป็นจริงและเชื่อถือได้

6. ห้าม privileged: true

container ทำได้แทบทุกอย่างบน host

Supply Chain

Scan image หาช่องโหว่ก่อน deploy

# Docker Scout (มากับ Docker Desktop)
docker scout quickview ghcr.io/mercent/shop-api:1.4.2
docker scout cves ghcr.io/mercent/shop-api:1.4.2

# Trivy (open source, ใช้ใน CI ได้)
trivy image --severity HIGH,CRITICAL --exit-code 1 \
  ghcr.io/mercent/shop-api:1.4.2

Production Checklist

Checklist ก่อนขึ้น Production

  • ☐ image tag แบบ immutable (version + sha)
  • ☐ multi-stage, non-root, base image ล่าสุด
  • ☐ scan ไม่มี CRITICAL
  • ☐ healthcheck + restart: unless-stopped
  • ☐ จำกัด CPU / RAM และขนาด log
  • ☐ secret ไม่อยู่ใน image / Git
  • ☐ DB ไม่เปิด port สู่ภายนอก, มี backup ที่ทดสอบ restore แล้ว
  • ☐ migration แยก job และย้อนกลับได้
  • ☐ รู้ขั้นตอน rollback ไปเวอร์ชันก่อน
  • ☐ แอปปิดตัวสุภาพเมื่อได้ SIGTERM
