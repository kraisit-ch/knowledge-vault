HTTP Status

Status Code ที่ทีมใช้ (และความหมายฝั่ง UI)

200

OK · แสดงข้อมูล

201

Created · toast “บันทึกแล้ว”

204

No Content · ลบ/อัปเดตสำเร็จ

400

Validation · แสดง error ใต้ช่อง

401

ไม่ได้ login / token หมดอายุ · refresh หรือพาไปหน้า login

403

ไม่มีสิทธิ์ · หน้า “ไม่มีสิทธิ์เข้าถึง”

404

ไม่พบ · หน้า not-found

409

Conflict · ข้อมูลถูกแก้ไปแล้ว / สถานะไม่อนุญาต

500 = bug ของเรา เสมอ ห้ามใช้ 500 แทน validation error และห้ามตอบ 200 พร้อม {"success": false}
Errors

Error format เดียว: ProblemDetails

// 400 Bad Request
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "traceId": "00-7a3f...-01",
  "errors": {
    "email": ["อีเมลนี้ถูกใช้แล้ว"],
    "items[0].quantity": ["ต้องมากกว่า 0"]
  }
}

// lib/api-error.ts (Next.js)
export function applyServerErrors<T extends FieldValues>(
  err: ProblemDetails,
  setError: UseFormSetError<T>
) {
  for (const [field, messages] of Object.entries(err.errors ?? {})) {
    setError(field as Path<T>, { message: messages[0] });
  }
}
แสดง traceId เล็ก ๆ ในหน้า error เพื่อให้ผู้ใช้แจ้งทีม Support แล้ว Backend ค้น log ได้ทันที

Auth

Authentication ระหว่าง Next.js กับ .NET

Browser
→ login →
Next.js (Auth.js)เก็บ session ใน httpOnly cookie
→ Bearer JWT →
.NET APIAddJwtBearer + Policy

แนะนำ

  • Token อยู่ใน httpOnly + Secure + SameSite cookie
  • Access token อายุสั้น (5–15 นาที) + refresh token
  • .NET ตรวจ issuer, audience, lifetime, signature ทุกครั้ง
  • สิทธิ์ใช้ policy เช่น RequireAuthorization("orders:write")

หลีกเลี่ยง

  • เก็บ JWT ใน localStorage (โดน XSS ขโมยได้)
  • เช็คสิทธิ์แค่ซ่อนปุ่มใน UI
  • ใส่ข้อมูลลับใน payload ของ JWT (decode ได้ทุกคน)
Security

CORS และ Security ที่ต้องตั้งเสมอ

builder.Services.AddCors(o => o.AddPolicy("web", p => p
    .WithOrigins(builder.Configuration.GetSection("Cors:Origins").Get<string[]>()!)
    .AllowAnyHeader()
    .WithMethods("GET", "POST", "PUT", "PATCH", "DELETE")
    .AllowCredentials()));

builder.Services.AddRateLimiter(o => o.AddFixedWindowLimiter("api", l =>
{
    l.PermitLimit = 100;
    l.Window = TimeSpan.FromMinutes(1);
}));

ห้าม

AllowAnyOrigin() คู่กับ credentials

Rate limit

login, OTP, endpoint ส่งอีเมล

HTTPS + HSTS

ทุก environment ที่ไม่ใช่ local

Type Safety

Generate TypeScript client จาก OpenAPI

// .NET 9+ (Program.cs)
builder.Services.AddOpenApi();
app.MapOpenApi();               // /openapi/v1.json
app.MapScalarApiReference();    // UI สำหรับทดลองเรียก

// orval.config.ts (Next.js)
export default {
  shop: {
    input: "http://localhost:5080/openapi/v1.json",
    output: {
      target: "src/lib/api/generated.ts",
      client: "react-query",   // ได้ useGetOrders() พร้อม type
    },
  },
};

# package.json → "api:gen": "orval"
npm run api:gen   # รันทุกครั้งที่ Backend เปลี่ยน contract (หรือให้ CI รัน)
Evolution

เปลี่ยน API โดยไม่ทำให้ Frontend พัง

Non-breaking (ทำได้เลย)

  • เพิ่ม field ใหม่ใน response
  • เพิ่ม endpoint ใหม่
  • เพิ่ม query param แบบ optional

Breaking (ต้องวางแผน)

  • ลบ / เปลี่ยนชื่อ field
  • เปลี่ยน type เช่น number → string
  • เพิ่ม field บังคับใน request
  • เปลี่ยนความหมายของ status code
  1. เพิ่มของใหม่ข้างของเดิม (หรือ /api/v2) แล้ว mark ของเดิมเป็น [Obsolete]
  2. Frontend ย้ายไปใช้ของใหม่ แล้ว deploy
  3. ลบของเดิมหลัง monitor แล้วไม่มีคนเรียก
Team Agreement

สรุปข้อตกลงร่วม (ติดไว้ที่ README ทุกโปรเจกต์)

  • JSON เป็น camelCase, วันที่เป็น ISO 8601 UTC (2026-10-06T08:30:00Z)
  • เงินใช้ decimal ฝั่ง .NET และส่งเป็น number สูงสุด 2 ตำแหน่ง หรือ string
  • ID เป็น Guid/ULID ไม่เปิดเผย running number
  • enum ส่งเป็น string ("paid") ไม่ใช่ตัวเลข
  • ทุก error เป็น ProblemDetails + traceId
  • list endpoint มี pagination เสมอ
  • OpenAPI คือ source of truth, client ถูก generate
  • Breaking change ต้องประกาศในช่องทีมก่อน merge
