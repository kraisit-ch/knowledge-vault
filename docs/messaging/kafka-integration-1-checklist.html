Checklist ก่อนเริ่ม + ข้อความขอข้อมูล

Checklist ก่อนเริ่มพัฒนา

  • ☐ broker endpoint ครบทุก environment
  • ☐ ชื่อ topic อ่าน / เขียน / DLT
  • ☐ consumer group id
  • ☐ security config + credential (ผ่านช่องทางลับ)
  • ☐ ตัวอย่าง payload 3 แบบ: สำเร็จ, business error, ข้อมูลผิด
  • ☐ message key ที่ตกลงร่วมกัน
  • ☐ retry / DLT / retention policy
  • ☐ ACL ว่า service นี้ read/write topic ไหน
  • ☐ network access (VPN, whitelist, firewall)
  • ☐ contact support + แผน monitor lag / DLT
รบกวนขอข้อมูล Kafka สำหรับระบบ <ชื่อระบบ> ดังนี้ครับ

1. Bootstrap servers ของ DEV/UAT/PROD
2. Topic ที่ต้อง produce / consume / DLT
3. แต่ละ topic มีกี่ partition
4. Security protocol (PLAINTEXT, SSL, SASL_SSL)
5. SASL mechanism และวิธีรับ username/password
6. CA cert / client cert / key (ถ้าใช้ SSL/mTLS)
7. Message format: JSON, Avro หรือ Protobuf
8. Schema และ payload ตัวอย่าง
9. Message key ที่ต้องใช้
10. Schema Registry URL + credential (ถ้ามี)
11. IP whitelist / VPN / firewall ที่ต้องขอ
12. Retention policy ของแต่ละ topic
13. Retry / DLT policy ที่ต้องการ
14. Consumer group id ที่ควรใช้
15. Contact support / on-call
Message Contract

Message Format: เลือกแบบไหนดี

JSON

อ่านง่าย เริ่มเร็ว debug สะดวก (Demo ใช้แบบนี้)

ต้องทำเพิ่ม: validate ด้วย Zod / JSON Schema เองทั้ง producer และ consumer

Avro

มาตรฐานองค์กร รองรับการเปลี่ยน schema แบบมีกติกา

ต้องมี: Schema Registry ใช้ร่วมกัน

Protobuf

ข้อมูลเล็ก เร็ว contract ชัด ใช้ข้ามภาษาได้ดี

ต้องทำ: generate type/code จากไฟล์ .proto

Schema evolution: เพิ่ม field ใหม่แบบ optional ได้ แต่ ห้ามลบ / เปลี่ยนชื่อ / เปลี่ยน type โดยไม่แจ้ง consumer ทุกทีม เพราะ message เก่าในคิวยังเป็นรูปแบบเดิม
Message Contract

Order Event: ตัวอย่าง + Data Dictionary

{
  "orderId": "ORD-1234",
  "customerEmail": "customer@example.com",
  "items": [
    { "productId": "PROD-001", "name": "iPhone 15 Pro", "qty": 1 }
  ],
  "timestamp": "2026-05-26T10:00:00.000Z"
}
FieldTypeบังคับคำอธิบาย
orderIdstringYesรหัส order = message key
customerEmailstringYesอีเมลลูกค้า
itemsarrayYesรายการสินค้า (≥ 1)
items[].productIdstringYesรหัสสินค้า
items[].namestringYesชื่อสินค้า
items[].qtynumberYesจำนวน (> 0)
timestampstringแนะนำISO 8601 UTC
// order.schema.ts — schema เดียว ใช้ทั้ง producer (ก่อนส่ง) และ consumer (หลังอ่าน)
export const OrderEventSchema = z.object({
  orderId: z.string().min(1),
  customerEmail: z.string().email(),
  items: z.array(z.object({ productId: z.string(), name: z.string(), qty: z.number().int().positive() })).min(1),
  timestamp: z.string().datetime().optional(),
});
export type OrderEvent = z.infer<typeof OrderEventSchema>;
Message Contract

Message Key: เลือกตาม “ลำดับที่ต้องรักษา”

ต้องการลำดับแบบไหนKey ที่แนะนำ
event ของ order เดียวกันต้องเรียงกันorderId
event ของลูกค้าคนเดียวกันต้องเรียงกันcustomerId
ไม่สนลำดับ เน้นกระจายงานให้มากที่สุดไม่ใส่ key
CreatedORD-1
PaidORD-1
ShippedORD-1
↓ key เดียวกัน = partition เดียวกัน
Partition 2ลำดับถูกต้องเสมอ
สิ่งที่ต้องแก้ใน Demo: /api/produce ยังส่งโดยไม่มี key (ส่วน /api/retry ใส่แล้ว) ทำให้ event ของ order เดียวกันอาจไปคนละ partition และถูกประมวลผลสลับลำดับ
await producer.send({
  topic: "order-events",
  messages: [{
    key: order.orderId,                                        // ✅ เพิ่มบรรทัดนี้
    value: JSON.stringify(order),
    headers: { "x-correlation-id": order.orderId, "x-event-type": "OrderCreated" },
  }],
});
Message Contract

Headers: ข้อมูลประกอบที่ไม่ใช่ตัว payload

Headers ของ message ปกติ (แนะนำ)

  • x-correlation-id — ตามงานข้าม service
  • x-event-type — เช่น OrderCreated
  • x-schema-version — เช่น 1
  • x-produced-by — service ที่ส่ง

Headers เมื่อส่งเข้า DLT

Headerตัวอย่าง
x-failed-service มีแล้วinventory-service
x-error-reason มีแล้วProduct has 0 units
x-error-type เพิ่มBUSINESS / TRANSIENT / INVALID
x-retry-count เพิ่ม3
x-original-topic/partition/offset เพิ่มorder-events / 1 / 42
x-correlation-id เพิ่มORD-1234

ใน DLT ให้เก็บ payload เดิมไม่แก้ไข และใส่สาเหตุไว้ใน headers เพื่อให้ replay กลับไปได้ทันทีหลังแก้ปัญหา

// src/lib/kafka.ts
import { Kafka, logLevel } from "kafkajs";

const isSecure = process.env.KAFKA_SECURITY === "SASL_SSL";

export const kafka = new Kafka({
  clientId: process.env.KAFKA_CLIENT_ID ?? "order-system",
  brokers: process.env.KAFKA_BROKERS!.split(","),
  ssl: isSecure ? { ca: [process.env.KAFKA_CA_PEM!] } : false,
  sasl: isSecure ? {
    mechanism: "scram-sha-512",
    username: process.env.KAFKA_USERNAME!,
    password: process.env.KAFKA_PASSWORD!,
  } : undefined,
  logLevel: logLevel.WARN,
});
