Business Problem

ทำไมระบบจึงไม่ควรทำทุกอย่างพร้อมกัน

ระบบแบบรอทุกขั้นตอน

  • ลูกค้าต้องรอนานขึ้น
  • ระบบหนึ่งล่มอาจทำให้กระบวนการทั้งหมดล้ม
  • รองรับปริมาณงานช่วง Peak ได้ยาก
  • ระบบต่าง ๆ ผูกติดกันมากเกินไป

ระบบแบบ Asynchronous

  • ระบบหลักตอบลูกค้าได้เร็วขึ้น
  • งานที่เหลือสามารถทำต่อเบื้องหลัง
  • เพิ่ม Worker เพื่อรองรับปริมาณงานได้
  • ระบบปลายทางล่มชั่วคราว งานยังรอได้

RabbitMQ

02

เปรียบเหมือน: ศูนย์คัดแยกพัสดุ

ตอบคำถาม: “ข้อความนี้ควรส่งไปที่ไหน?”

BullMQ

03

เปรียบเหมือน: กระดานมอบหมายงาน

ตอบคำถาม: “มีงานอะไรที่ Worker ต้องทำ?”

Kafka เน้น “เหตุการณ์” — RabbitMQ เน้น “การส่งข้อความ” — BullMQ เน้น “การทำงานให้เสร็จ”

หัวข้อ Apache Kafka RabbitMQ BullMQ

Apache Kafka

เหมาะเมื่อ Event คือสินทรัพย์ข้อมูลขององค์กร

แนวคิดสำคัญ

  • Topic และ Partition
  • Offset ติดตามการอ่าน
  • Consumer Group
  • Retention Policy

Use Case ที่เหมาะ

  • Enterprise Event Backbone
  • Customer Activity Stream
  • Change Data Capture (CDC)
  • Data Lake & Analytics Pipeline
RabbitMQ

เหมาะเมื่อหัวใจคือการส่งและคัดแยกข้อความ

วิธีทำงาน

Producer → Exchange → Queue → Consumer

  • รองรับ Acknowledgement
  • รองรับ Dead Letter

Use Case ที่เหมาะ

  • Payment และ Order Processing
  • Routing ตามประเภทหรือภูมิภาค
  • Command ระหว่าง Microservices
BullMQ

เหมาะกับ Background Job ของ Node.js Application

สถานะของ Job

Waiting → Active → Completed / Failed

  • Retry & Backoff
  • Rate Limiting

Use Case ที่เหมาะ

  • ส่ง Email หรือ Notification
  • สร้าง PDF / Report
  • Import / Export ไฟล์
  • เรียก External API ที่จำกัด Rate
Existing Platform Strategy

ถ้าลูกค้ามีเครื่องมืออยู่แล้ว ควรตัดสินใจอย่างไร

มี Kafka อยู่แล้ว

ใช้ต่อเมื่อเป็น Event, ต้อง Replay หรือทำ Data Pipeline

มี RabbitMQ อยู่แล้ว

ใช้ต่อเมื่อเป็น Message/Command และ Routing ตอบโจทย์

มี BullMQ / Redis

ใช้ต่อเมื่อเป็นงาน Node.js ที่เน้น Retry, Delay และ Rate Limit

Final Recommendation

เลือกเครื่องมือที่ง่ายที่สุด ซึ่งตอบโจทย์ได้ครบ

Kafka

เลือกเมื่อ Event เป็นสินทรัพย์ข้อมูล

เก็บย้อนหลัง, มีหลาย Consumer, ทำ Data Pipeline

RabbitMQ

เลือกเมื่อหัวใจคือ Message และ Routing

ส่ง Command ไปปลายทาง, มี Acknowledgement

BullMQ

เลือกเมื่อหัวใจคือ Background Job

Node.js/TypeScript, ต้องการ Retry, Delay และ Rate Limit
